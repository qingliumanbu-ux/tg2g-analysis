# 太钢后台 SQL 达梦适配

将用户指定范围的应用 SQL 转为 DM8 支持、保持业务含义的写法，交付源码差异、处理台账和人工复核清单。先判断本次要求是研究、转换还是复核；仅研究/复核时不修改业务代码，创建或调用本技能本身不扩大授权范围。

开始项目工作时读 [项目上下文](references/project-context.md)，定位当前主方案、清单与既有改动。以用户最新说明和当前源码为准，先核对工作区差异，保护已有工作。

## 约定

- 用户负责应用 SQL 适配，BM2 连接、命令、模型、绑定、分页、类型转换及事务已有达梦适配。检查业务自有分支和 SQL，不重做平台、迁库、部署或全项目联调。
- 开始转换不依赖完整构建包、全库 DDL、样本或双库环境；仅为确实受影响的语句请求局部契约。
- 以完整 SQL 模板及其执行分支为处理单位。文件命中数、关键词数、历史副本数与 SQL 完成数分别统计。
- **每处实际改写先保留完整原 SQL 为源码注释，再写活动的 DM8 SQL。** 包括原字符串拼接、变量、参数及所有片段。执行改写前读取 [注释格式](references/comment-format.md)；已有改写缺注释时，从可信基线恢复并补齐，不靠记忆重构原句。
- 改写按 [转换规则](references/conversion-rules.md) 的 T1—T15 执行；该文件同时给出"可保留"白名单（MINUS、CONNECT BY、LISTAGG、PIVOT、LENGTH2、REGEXP_*、SYS_GUID、(+) 等，均附官方依据）与"待口径挂起"策略（如 TIMESTAMPDIFF 按服务分别提请人工选择，其余方言可先行转换并整块挂起）。
- 日期口径、空值、字段长度或其他会改变结果的语义无法确定时，给用户具体复核项，等待该项结论再改，继续推进其他确定项。用户复核结论是业务选择，不能替代目标 DM8 执行证据。
- 以 WMSM、MMSM、TMSM 等二级模块作为用户检查点。模块内部持续处理确定项；模块完成报告交付后停止，等用户决定是否进入下一个模块（用户另有指示除外，如"全部模块处理一遍再精修"）。

## 工作流程

### 1. 确定本批范围和 SQL 来源

复用已有扫描并核对当前文件版本。搜索 SQL 和数据库调用点，反向追踪字符串来源，覆盖查询/新增/修改/删除、批量写入、公共函数、内嵌 DDL/过程块、过程调用、动态配置以及客户端发送的 SQL。检查 SQL 文件、脚本和归档的来源身份。

**SQL 块识别必须按内容而非变量名白名单**:任何赋值语句，只要其字符串以 select/insert/update/delete/merge/with/values 开头即入块。本项目实证过的漏检形态清单(审计必查):`c_sql_condition`/`strSql2`/`vtable` 等非 sql 前缀命名;`sprintf(sql, "…")` 格式化;`CDbCommand name("…", conn)` 构造式内联;`sqlstr += "…"` 纯片段追加(不含 SELECT 关键词,过滤规则需豁免追加块);块内空行不截断、遇到新赋值才截断;C++ 方法(如 `SubstringNE`、`QUERY()`)是提取误报需排除。

**扫描器的方言模式集必须与改写规则同步**(每加一条 T 规则同步更新扫描正则);扫描失败要显式报错,禁止静默用旧数据继续。跨文件编号全局唯一,收尾时必须做唯一性断言。

用能识别宿主语言字符串和注释的方式区分活动代码、保留的原 SQL、普通注释和历史副本。新增的原 SQL 注释仍进入历史记录，但不得计为活动方言残留。现有正则扫描无法可靠区分时，逐项人工判别，不把命中清零当作验收标准。

完成条件：本批有可定位的完整 SQL、拼接变体、执行入口及版本；源码外文本未取得、未命中文本、二进制和副本均有范围说明。

### 2. 逐条判断

核对原 SQL 的参数、结果列、读取类型、排序/汇总、读写条件、日期单位、空值、锁及事务边界。按实际目标版本查 DM 官方语法；源码含 DB2 等写法时核对源厂商语义，不推断现网产品。

- 支持且符合当前契约：保留，记录依据；无需人为制造新旧两份相同 SQL。
- 差异明确且能保持结果：制定局部改写。
- 语义不明：进入人工复核清单，使用稳定编号，避免同一问题重复提问。
- 文本或平台定义缺失：记录具体所需项，继续其余条目。

对 DatabaseKind 核对 DM 的真实映射；不发明枚举或自行设置兼容模式。共用分支按用户的 DM8 目标记录影响，不顺便承诺旧多库兼容。日期边界与实际时长、DB2 两参数 TIMESTAMPDIFF 与 DM 三参数形式不能只按名字替换。动态执行器可保留不代表传入文本已适配。

人工复核项写清：编号、源码位置与表达式锚点、完整 SQL 的出处、原意证据、建议方案及前提、不同选择的结果差异、一个明确问题、用户结论和后续处理。示例使用脱敏常量，标为理论期望；确有推荐时解释理由，证据不足时不代选。只有收到真实答复才填写确认人/结论。

完成条件：每条归入可保留、可转换、待人工复核、待局部信息或范围外，理由可追踪。只关闭所列条目，不从片段推导整个服务完成。

### 3. 保留原句并改写

改前核对当前代码与台账。按注释格式保留最初原 SQL，说明改动原因、保持的业务含义、必要前提及条目编号；其后放活动 DM8 SQL。重复处理同一语句时复用原注释和编号，更新说明，不层层复制历史块。

只改 SQL 差异及其必需配套，保持参数绑定、结果契约和控制流。保留实测编码、BOM、换行和宿主语言格式，不假定 Windows 文件一定是 CRLF。保护真实凭据，注释和报告中的敏感值必须脱敏。

完成条件：每条改写都有完整原 SQL 注释和唯一活动版本，未混入无关重构，未越过待人工确认的业务选择。

### 4. 静态复核本批

核对完整拼接和关联查询；检查修改条件、参数顺序、列别名、聚合/排序及事务位置。复搜活动代码中的旧模式，排除保留原句造成的历史命中，并逐项解释残留。

**逐模板函数核对**:将本批语句按模板去重,提取每个模板的函数名与特殊标记,对照 DM8 官方函数/语法支持清单;不在清单中的逐个查证(官方手册或社区确认),不支持的实施改写。本轮实证为支持的 Oracle/DB2 特性白名单见[转换规则](references/conversion-rules.md);DB2 `DIGITS()`(零填充语义)与两参数 TIMESTAMPDIFF 同属"需人工口径/语义确认"类。

每个文件做三项断言:①去掉新增注释后与改前逐字节一致;②转换规则对原句幂等;③活动代码方言残留复扫(排除保留原句与挂起语句)。文件编码按原样自适应写回(不假定 GB18030 或 UTF-8),换行保持。

检查源码差异与空白(`diff --check`;注释保留的原行既有行尾空白属可接受提示,需逐条说明)。仅补注释时，去掉新增注释后应逐字节还原改前版本；通常的 SQL 转换同时核对预期可执行差异，不能用“注释检查通过”代替语义复核。

按用户范围不构建全项目、不搭数据库测试工程。适用时提出小范围 SQL 验证样例供后续使用；只有实际执行过才记录运行结果。

完成条件：本批每条修改有静态复核记录，残留和待确认项明确。文件或服务还有未处理 SQL 时保持部分完成。

关闭二级模块前读取[模块完成与 SQL 等价性验收规范](<D:/work/company/太钢二炼钢/analysis/dameng-migration/模块完成与SQL等价性验收规范.md>)。分别记录 E1 静态契约、E2 DM8 可执行、E3 原/目标差异等价和 E4 应用路径证据。静态推导不能写成实际执行或结果等价；没有环境时生成验证材料并保留“未验证”。

### 5. 更新记录并交付

沿用项目台账和转换日志，保留扫描快照，更新当前版本定位；重新生成机器清单时保留人工决定。

每条至少记录：编号、模块/文件/函数、版本及当前行号、原 SQL 注释位置、目标 SQL 位置或保留理由、来源类型、参数/结果语义、依据、分支影响、处理状态、人工结论（如有）、验证证据。

处理状态区分待审查、可保留已复核、已转换已复核、待人工复核、待局部信息及范围外。运行状态单独记录未执行或实际结果。代码改过但语义仍待确认的部分，不能算“已转换已复核”。

交付本批改动、处理统计和人工复核清单。所有在手条目关闭后才称该范围源码适配完成；未取得的动态 SQL 明列为缺口，不从分母中静默删除。

到达二级模块边界时，使用项目模板提交模块完成报告，明确模块审查、源码适配、DM8 可执行和结果等价四个状态。报告完成后停止，不开始下一模块，等待用户审核和选择。
