## 2. 三条共性改写规则

改写前先确定"哪张表是被保留侧"：`(+)` 标注的那张表是**可为 NULL 的补充侧**，另一侧被保留。

| 规则 | 内容 |
|---|---|
| **R1** | `X.col = Y.col(+)` → `X LEFT JOIN Y ON X.col = Y.col`。被保留侧 X 放最左。 |
| **R2** | `Y.col(+) = X.col` → 同样先判方向：`(+)` 在 Y 上，则 Y 为补充侧，X 被保留 → `X LEFT JOIN Y ON X.col = Y.col`。**不能只看谁写在左边**。 |
| **R3** | **逗号连接与 JOIN 混用的陷阱**：JOIN 的优先级高于逗号，`FROM A, B LEFT JOIN C ON A.x=C.x` 会解析成 `A, (B LEFT JOIN C)`，此时 `ON` 引用了 JOIN 单元之外的 `A`，属无效引用。正确做法是把被保留表放到 LEFT JOIN 链的最左，剩余内连接表以逗号接在链**后面**。 |

## 4. 改写前必须确认的语义项（提请人工复核）

1. **`(+)` 侧表的筛选条件留在 WHERE 还是挪进 ON，会改变结果。**
   典型：`#7`。原语句是 `WHERE(a.st_no(+) = b.st_no <sqlstr_temp>)`，而 `sqlstr_temp` 含 `AND A.CAST_LOT_NO = '…'`（`A` 即 `(+)` 侧）。在 Oracle 语义下，对 `(+)` 侧的非 `(+)` 谓词会把 NULL 补齐行过滤掉——即**传了浇次号时实际退化为内连接，不传时才是真外连接**。本方案把 `sqlstr_temp` 留在 WHERE，**恰好保持这一现状**；若有人把它挪进 `ON`，行为会变成"始终保留 b 行"，属语义变更。**建议明确：保持现状，除非业务上本来就想要真外连接。**

2. **`#4` 是否真的会执行。** 它在 `DB_KIND_ORACLE` 分支内。若 DM8 的 `DatabaseKind` 映射不是 ORACLE，此句不执行，改写紧迫性下降——但**仍建议改**，因为它不可移植。需先确认 BM2 的 DatabaseKind 实际取值。

3. **`#9` 等的 `(+)` 方向已逐处判过**，但改写后建议用真实数据核对**行数**：外连接改写最常见的错误就是方向反了，而方向反了通常表现为行数变多或变少，容易发现。

## 5. 怎么优化（执行建议）

1. **先做一次 E2 实测，再决定改写优先级。** 在目标库上直接跑一条最小 `(+)` 语句（`verify/probes/probe-01-syntax.sql` 的 `WL-ORACLE-OUTERJOIN`）：
   - 若报错 → 12 处必须改，优先级最高；
   - 若能执行 → 仍建议改（不可移植、且与官方文法不符），但可与其它工作并行、不阻塞上线。
   这一步能把"要不要改"从推测变成事实。

2. **按风险分批，而不是按模块。** 建议顺序：
   - 第 1 批：#5、#6、#7、#8 —— MMSM 四处，格式高度同型（`a.xxx = b.plan_no(+)`），可一次改完并统一核对；
   - 第 2 批：#10、#11、#9 —— PSSM 三处，其中 #10 还需验证派生表内 `ORDER BY`；
   - 第 3 批：#1、#2、#3 —— WMSM 三处，其中 #2/#3 含反斜杠续行，需注意续行符与空格；
   - 第 4 批：#12 —— 唯一需要"把被保留表提到链首、内连接表逗号接后"的复杂结构，单独做；
   - 最后：#4 —— 待 DatabaseKind 确认后再定。

3. **统一按项目规范落注释**：每处保留完整原 SQL + `// DM8 SQL：` + 唯一活动版本，用全局唯一 CHANGE 编号。`#2/#3` 的反斜杠续行必须原样保留，不能替换成字符串拼接——否则"去掉新增注释后应逐字节还原"这条断言会失效。

4. **改写不是全部优化项。** 顺带值得一并处理的（都与本次 12 处同文件、同函数，一次进文件就能做完）：
   - `#3` 所在文件的 `KEEP-wmsm01q0q_inq1-03` 台账证据仍写"无方言差异"，建议同步更正；
   - `#11` 的 `sqlPlanStr` 与 `#12` 的 `sqlstr_count`（`FROM TPSSM11 A, TPSSM12 B WHERE 1=1`，无 `(+)`）**不受影响，不要顺手改**。

5. **验证方式要诚实**。原 `(+)` 语句在 DM 上跑不起来，因此**无法在单库内做新旧对拍**。可行的证据只有两种：① 若有原 Oracle 库或历史黄金结果，做真正的 E3；② 否则用真实数据跑改写后的 ANSI 版，核对**行数与关键字段**，并把"未与原库对拍"如实写入证据栏。**不能因为 ANSI 版能跑通过就写"结果等价已验证"。**
