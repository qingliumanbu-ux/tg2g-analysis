其中必须特别注意两条：
- **R3 陷阱**：JOIN 优先级高于逗号，`FROM A, B LEFT JOIN C ON A.x=C.x` 会解析成 `A,(B LEFT JOIN C)`，`ON` 引用到单元外的 `A` 属无效引用。正确写法是把被保留表放链最左、其余内连接表用逗号接在链后。涉及 #1 与 #12。
- **筛选条件必须留在 WHERE**：对 `(+)` 侧的非 `(+)` 谓词，原 Oracle 语义会过滤掉 NULL 补齐行（传参时实际退化为内连接）。挪进 `ON` 会改变结果集。典型是 #7。

#### A2. `INT('…')` —— 13 处，需实测确认

**位置**：`WMSM/libWMSM/f_wmsmsm_cranecmd_check.cpp`，活动代码，**无条件执行**。L120 / L128-130 / L144 / L152 / L158 / L170 / L176，共 13 处、跨 8 条语句。

```cpp
sqlstr = "SELECT * FROM TWMA7 WHERE CRANE_CMDGRPNO = INT('" + twma7["CRANE_CMDGRPNO"].ToString() + "')";
```

**官方依据**：DM8 官方函数手册的**类型转换函数只有 9 个**（`CAST`/`CONVERT`/`HEXTORAW`/`RAWTOHEX`/`BINTOCHAR`/`TO_BLOB`/`UNHEX`/`HEX`/`CHARTOBIN`），**数值函数 41 个中也没有 `INT`**；官方"字符串转整型"示例一律用 `CAST('123' AS INT)` 或 `TO_NUMBER`。`INT(x)` 是 DB2 写法。

**判定**：不在官方清单、高度可疑、**需实测**。**不判定"不支持"**——DM 有 `COMPATIBLE_MODE=8`（部分兼容 DB2），该模式行为文档未载。

**若确认不支持**，改写是机械的：`INT('…')` → `CAST('…' AS INT)`。**这 13 处同生共死**，在库里试一条即可定全部。

### 2.4 【顺手查实的两条高价值结论】

1. **空串/NULL 语义由 `COMPATIBLE_MODE` 决定**。官方原文："默认 0 的情况下，达梦视 null 不等同于空字符串…会导致 is null 查不出全部数据"；FAQ 另有"COMPATIBLE_MODE=2 后 is null 无法查出空字符串数据"。
   → **验证任何空值语义前，必须先确认目标库 `COMPATIBLE_MODE` 的取值**，否则结论不可移植。这直接关系 HR-003 与 CHANGE-388（`COALESCE(LENGTH(TRIM(SM_PLAN_NO)),0)=0`）。
2. **官方示例显示 `''` 与 `NULL` 在默认库下表现一致**（多表联合检索文档的 union all 示例）。可作 CHANGE-388 类改写的旁证，但仍以目标库实际参数为准。
