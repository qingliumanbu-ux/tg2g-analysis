# 达梦 SQL 转换离线校验器 · 使用说明

面向场景：**已连 VPN（能访问达梦库，但完全没有外网）**，需要在没有在线 AI、没有达梦客户端、没有外网文档的条件下，自己把 SQL 转换结果批量验证完。

配套文件：

| 文件 | 作用 |
|---|---|
| `dm8check.py` | 校验器主体：批量执行、结果落盘、新旧写法对拍 |
| `dm8conn.json` | 连接参数（主机、驱动、JVM 路径）。**不含密码** |
| `probes/probe-01-syntax.sql` | 方言支持探针，46 条，全部只依赖 DUAL，不碰业务表 |
| `probes/diff-01-equivalence.sql` | 新旧写法对拍，9 条 |
| `run-verify.cmd` | 一键启动（双击或命令行传参） |
| `out/` | 结果 CSV 输出目录，自动创建 |

## 一、为什么断网也能跑

三个依赖项全部落在本机，运行时不需要任何外网：

1. **JVM** —— 直接复用 DBeaver 自带的运行时 `D:\tools\DBeaver\jre`（已验证可启动，`jvm.dll` 正常）。
2. **达梦 JDBC 驱动** —— 复用 DBeaver 已下载的 `DmJdbcDriver18-8.1.3.62.jar`，无需再获取。
3. **Python 依赖** —— `jaydebeapi` 与 `JPype1` 已在联网窗口装进隔离环境 `C:\Users\AIGC\.workbuddy\binaries\python\envs\default`。

> 注意：DBeaver 自带的是裁剪版运行时（无 `javac`、无 `jdk.compiler`），所以**不能**用它编译 Java 程序。本项目改用 Python + JDBC 桥接，绕开了这个限制。

## 二、使用步骤

### 第 0 步：连上 VPN

只有连上 VPN，达梦库 `10.76.53.52:5236` 才可达。先自检：

```cmd
run-verify.cmd selftest
```

看到 `网络连通 : 是` 即可继续；若为 `否`，先解决 VPN。

### 第 1 步：把用户名填进配置（一次性）

打开 `dm8conn.json`，把 `"user"` 从空串改成你的达梦用户名。用户名不是密钥，可以落盘。

**密码不要写进任何文件。** 两种给法，任选其一：

- 运行时交互输入（最省事，`run-verify.cmd` 会提示）；
- 或先设环境变量：`set DM8_PASSWORD=你的密码`，再运行。

### 第 2 步：先跑不依赖表的探针

```cmd
run-verify.cmd probe
```

这一步只验证方言本身，不依赖业务表是否已迁移，是最干净的一层结论。46 条里：

- 标 `NEG-` 的 2 条**必须失败**。如果它们显示成功，说明校验器判读不可信，先查工具链再看别的结论。
- `T12-EMPTY-IS-NULL` 直接告诉你当前库"空串是否等同 NULL"，这决定了 CHANGE-388 这类改写在本库的必要性和写法。
- `HR002-NEG-HOUR` / `HR002-SEC2MIN` 给出负时差和截断方向的实测值，是核对该服务口径的直接证据。

### 第 3 步：跑新旧写法对拍

```cmd
run-verify.cmd diff
```

`OLD_V` 是原写法、`NEW_V` 是转换后写法，逐行比较。带 `口径观测-` 前缀的用例**预期就可能不同**，是拿来量化口径差异的，不算缺陷；其余的必须显示"一致"。

### 第 4 步：跑存量 E2 脚本

```cmd
run-verify.cmd e2
```

默认执行 `../e2-verify-*.sql`（14 个文件、377 条）。脚本在读取时会做两项自动归一化，**不会改动源仓库里的原文件**：

- 删除 C++ 注释残留行（如 `e2-verify-pssm.sql` 里 CHANGE-122 的 `// DM8 SQL：;`）；
- 把参数占位替换产生的非法限定名 `'测试值'.列名` 还原成裸列名（如 CHANGE-115/117 的 `TRIM('测试值'.FACTORY_DIV)`）。

这两类问题原本会让整份脚本执行中断，属于生成脚本的缺陷，不是方言问题。

**语句数对账：标注 377 条 → 实切 368 条，差的 9 条全部有据可查**（都是脚本里"无法提取 SQL"的占位标签，本身没有语句，不是被漏解析）：

| 文件 | 标签数 | 实切 | 差额 | 原因 |
|---|---|---|---|---|
| `e2-verify-wmsm.sql` | 119 | 112 | 7 | CHANGE-95/96/97/102/103/104/372 为多行拼接或无法提取，脚本内仅存说明 |
| `e2-verify-tmsm.sql` | 19 | 18 | 1 | CHANGE-114「无法提取 SQL」 |
| `e2-verify-pssm.sql` | 39 | 38 | 1 | CHANGE-122 只剩注释行，无有效语句 |
| 其余 11 个文件 | 200 | 200 | 0 | 全部一致 |

另有 2 处脚本自身的引号不平衡，工具会在加载时提示、不会让它污染后续语句：

- `e2-verify-tmsm.sql:L14`（CHANGE-113 的 UPDATE，23 个单引号，奇数）
- `e2-verify-wm00.sql:L16`

CSV 里 `语句完整` 列会标出「未以分号结束」的条目，`疑似残缺` 列标出变量被剥离后剩下的残缺表达式（如 `ROUND(/60,2)`）。这两类都属脚本缺陷，**不要记成方言转换失败**。

也可以只跑指定文件：

```cmd
run-verify.cmd e2 --files ..\e2-verify-wmsm.sql
```

### 第 5 步：只做离线盘点（不需要连库）

```cmd
run-verify.cmd list
```

输出每条语句的标签、来源行、语句摘要，用于确认分母，不连库、不登录。

## 三、结果怎么看

CSV 输出在 `out/`，按 `e2-`、`probe-`、`diff-`、`清单-` 前缀加时间戳区分。关键列：

| 列 | 含义 |
|---|---|
| `结果` | 成功 / 失败 / 跳过(写操作) |
| `错误分类` | 失败时自动归类，见下 |
| `错误码` | 达梦错误码（能从报文里提取时才有） |
| `返回列数`、`返回行数` | 成功时用于确认结果集形状没变 |
| `错误信息` | 原始报文，已压成单行、截断 400 字 |

**错误必须先分诊，再判读**，否则会把环境问题当成方言问题：

| 分类 | 含义 | 处理 |
|---|---|---|
| 语法或函数不支持 | 真正的方言问题 | 必改 |
| 对象不存在 | 库内缺表/列/视图，属环境缺口 | 不计为方言失败，等表结构到位再跑 |
| 权限不足 | 账号权限 | 换账号或补授权 |
| 数据类型或长度 | 类型/长度语义差异 | 按具体列核对 |

## 四、安全约束（已内建）

- **默认关闭自动提交**，每条语句执行后回滚。DBeaver 那个连接是 `auto-commit=true`，在 GUI 里做 DML 验证会真提交——这个工具刻意避开了这个坑。
- 遇到 `INSERT/UPDATE/DELETE/MERGE/TRUNCATE/DROP/ALTER` 一律**跳过**，除非显式加 `--allow-dml`（即使加了也会回滚）。
- 密码只从环境变量或交互输入读取，不写入任何文件、不出现在 CSV 与日志里。

## 五、已知限制（不要扩大结论）

1. **没有原库。** 本机 DBeaver 只有达梦连接，没有 Oracle/DB2 数据源，因此验收规范里的 E3"原库与目标库差异对比"**在本机无法照原样执行**。本工具做的是：E2（可执行）+ 同库双写法对拍（语义验证的替代手段）。真正的双库 E3 需要原库或一份可信的黄金结果。
2. **DB2 专有写法无法对拍。** `SYSIBM.*`、两参数 `TIMESTAMPDIFF`、`DIGITS()` 等在 DM8 上根本执行不了，只能做 E2 语法验证，不能做新旧结果对比。
3. **DUAL 探针覆盖不到表相关的行为**，典型的是 CHAR 定长列的尾空格比较（`CAST_NO <> ' '`、`STEEL_RETURN_CODE = ' '`）。这类必须在表结构到位后用真实列验证。
4. **静态推导不等于执行证据。** 探针通过只能说明该写法在本库这个版本、这套参数下能跑；不能推广到"所有数据下结果等价"。
5. **并发与锁无法用单会话证明。** 序列取号、`FOR UPDATE` 的并发语义需要两个会话同时压，本工具是单连接串行执行。

## 六、每条结论要留的证据

按验收规范要求，写入台账或批次记录时至少包含：

- SQL 编号（CHANGE-xxx）与来源文件/函数；
- 达梦小版本（`probe-01` 的 `ENV-VERSION` 那条会给）、兼容模式、字符集、空串是否等同 NULL；
- 执行的语句原文或哈希、实际参数（脱敏）、执行时间、结果摘要、错误码与分类；
- 结果 CSV 的文件名，作为可回溯证据。

**没有实际执行记录的条目，状态继续写"未执行"。** 探针通过不等于模块验证通过。
