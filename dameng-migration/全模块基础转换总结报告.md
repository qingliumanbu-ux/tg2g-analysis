## 3. 转换规则(15 类,均有官方依据;详见各批次记录)

| 规则 | 内容 | 依据 |
|---|---|---|
| T1 | SYSIBM.SYSDUMMY1/SYSIBM.DUAL/sysibm.* → DUAL | DM DUAL;CHANGE-01/02 先例 |
| T2 | `± N DAY(S)` → `± N` | DM 日期运算:整数以天计 |
| T2b | 表达式级天数标注(如 `DAYOFWEEK(x) DAYS`)去掉后缀 | 同上 |
| T3 | `DAYS(A)-DAYS(B)` → `DATEDIFF(DAY,B,A)` | IBM DAYS + DM DATEDIFF |
| T4 | `DECODE(x,NULL,a,b)` → `CASE WHEN x IS NULL …` | 标准 SQL;规避 DM DECODE 未记载 NULL 语义 |
| T5 | 二元标量 `MAX(a,b)` → 空值守卫 GREATEST | IBM 标量 MAX 空值传播;DM GREATEST 仅用于双非空 |
| T6 | ROWNUM 别名 → RN | DM ROWNUM 为伪列关键字 |
| T7 | CREATE SEQUENCE 只留 DM 支持子句(去 AS INT,NO CACHE→NOCACHE) | DM 序列 DDL 官方语法 |
| T8 | `values nextval for x`/`nextval for x` → `x.NEXTVAL`(必要时 from DUAL) | DM 序列伪列 |
| T9 | `value(a,b)` → `nvl(a,b)` | DM 空值函数表无 VALUE |
| T10 | `SUBSTR2` → `SUBSTR`(位置 0 显式改 1) | DM 无 SUBSTR2 |
| T11 | `INTERVAL 'n' HOUR` → `n.0/24` | DM 日期运算官方示例 |
| T12 | `DECODE(x,'',a,b)` → `CASE WHEN x IS NULL OR x='' …` | 同 T4,含空串配置鲁棒性 |
| T13 | `± N HOUR/MINUTE/SECOND` → `n.0/24、n.0/1440、n.0/86400` | DM 日期运算官方示例 |
| T14 | `current date/time/timestamp/schema` → `CURRENT_*` | DM 官方函数手册 |
| T15 | DB2 `POSSTR(源,子)` → `INSTR(源,子)` | POSSTR 不在 DM 函数手册;INSTR 为官方字符串函数,参数序与返回一致 |

保留不改:NVL、无 NULL/空串搜索的 DECODE、普通 ROWNUM、SYSDATE 及小数天运算、日期相减×24、FETCH FIRST、seq.NEXTVAL、FOR UPDATE、Oracle `(+)` 外连接(4 处,备注 E2 回退方案)、DB2 分支内系统目录查询(sysibm.systables/syscolumns,8 条,分支守卫+台账标注)。

## 7b. 嵌入式 SQL(EXEC SQL)发现(2026-09-06 自查轮第三遍)

全工作区搜索发现 **30 个文件、101 条 `EXEC SQL` 嵌入式语句**,分布在 7 个模块(SM00 81 处、WM00 45 处、WMSM 16 处、PSSM 13 处、TMSM 3 处、MM00 1 处、QMTS 1 处)。这些语句使用 DB2 风格的宿主变量语法(`:var`)和 `INTO :host_var` 子句,**不经 CDbCommand**。

经逐条提取检查:101 条语句均为标准 SQL,未发现 DB2 方言标记。但 **EXEC SQL 的执行机制完全不同于 CDbCommand**——需要数据库预编译器(IBM db2prep / DM dpc)在编译期将嵌入 SQL 翻译为函数调用。

**需要用户决策**:这 101 条语句的处理方式——
- 方案 A:保留 EXEC SQL 语法,确认项目构建系统支持 DM 的嵌入式 SQL 预编译器(dpc)
- 方案 B:改写为 CDbCommand 调用(工作量较大,但消除对预编译器的依赖)

已全部入账(sql_id 前缀 EXEC-),状态"可保留"但标注了基础设施依赖。
