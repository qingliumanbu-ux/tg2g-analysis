# 模块完成与 SQL 等价性验收规范

更新时间：2026-09-06。本文规定 WMSM、MMSM、TMSM 等二级模块什么时候可以停下来汇报，以及如何证明 DM8 SQL 可执行、与原 SQL 行为一致。

## 1. 模块边界先写清

开始模块前，在模块报告中定义本次分母。默认包括该 `Server/<模块>` 仓库的全部活动应用 SQL，以及能够明确映射到该模块、会向后台发送 SQL 的客户端或配置来源。共享库、外置配置和归档副本分别登记来源和责任，不能不说明就从分母中删除，也不能重复计数。

文件数、关键词命中数、SQL 数分别统计。一条逻辑 SQL 有明确的数据库分支或动态变体时，台账中分别记录其变体；原 SQL 注释不计为新的活动 SQL。

## 2. 四个状态不能混称

| 模块状态 | 必须具备的证据 | 可以对用户怎么说 |
|---|---|---|
| 模块审查完成 | 模块范围内所有 SQL 已定位并分类，没有“尚未看”的活动 SQL | “本模块共识别 N 条，全部已有处理结论，其中 X 条仍待人工/局部信息。” |
| 模块源码适配完成 | 所有在手 SQL 均为“可保留已复核”或“已转换已复核”，没有待人工、待局部信息和未取得的动态文本 | “源码适配完成；运行证据见下列等级。” |
| DM8 可执行已验证 | 模块全部目标 SQL 在指定 DM8 版本和配置下实际解析/执行成功，有语句、参数和结果记录 | “已在某 DM8 环境执行通过。”只覆盖实际记录的版本、配置和用例。 |
| 结果等价已验证 | 原 SQL 与 DM8 SQL 在同一逻辑数据和边界用例下完成差异对比，结果集或数据变更一致 | “在记录的用例和数据范围内等价。”不得扩大成所有可能数据的绝对证明。 |

“源码已改”“DM8 能运行”“结果与原 SQL 一致”是三件事。缺少运行环境时，Agent 仍可完成扫描和源码适配，但必须把后两个状态写成“未验证”，不能让用户用肉眼代替技术验证。

## 3. 单条 SQL 的证据等级

| 等级 | 证据内容 | 用途 |
|---|---|---|
| E1 静态契约复核 | 原 SQL、目标 SQL、参数、结果列、表、连接、过滤、排序、聚合、NULL、日期、类型、锁和事务逐项对照；改写有官方语法依据 | 证明改写有理由且没有明显改变业务契约 |
| E2 DM8 可执行 | 在明确的 DM8 小版本、兼容模式和相关参数下，使用脱敏参数实际解析或执行；记录成功/错误、返回列或影响行数 | 证明目标语法在该环境可执行 |
| E3 差异等价 | 原数据库执行原 SQL、DM8 执行目标 SQL；使用同一逻辑数据和参数，自动比较查询结果或写入后状态 | 证明记录范围内的行为一致 |
| E4 应用路径验证 | 通过真实 BM2 调用路径执行，核对绑定、读取类型、事务、错误处理和调用结果 | 证明 SQL 与应用代码组合后的行为 |

E1 可以由 Agent 独立完成。E2 需要可用的 DM8。E3 需要原数据库与 DM8，或一份可信的原系统黄金结果。E4 需要对应应用调用条件。用户只负责确认业务含义不明确的选择；技术证据由 Agent 或实际执行验证的人员产生并记录。

只有 DM8 环境时，可以证明 E2，不能直接声称 E3。没有原库但有改写前留存的可信输入、结果及数据库状态时，可以把它作为黄金基线进行比较，并明确基线来源。既没有原库也没有黄金结果时，最高只能给出 E1 静态结论和待执行验证材料。

## 4. E1 静态等价检查

每条 SQL 至少核对：

- 输入参数名称、顺序、类型、格式、NULL 可能性和绑定方式；
- SELECT 的列数、顺序、别名、类型、精度、NULL、重复行和排序；
- FROM、JOIN 类型、连接条件、WHERE/HAVING 条件及逻辑优先级；
- GROUP BY、聚合、DISTINCT、UNION/UNION ALL、分页和 Top-N 的处理次序；
- 日期的日历边界、实际经过时长、时区、格式及月末/闰日；
- 空串、空格、NULL、拼接及隐式类型转换；
- INSERT/UPDATE/DELETE/MERGE 的目标表、目标列、赋值、命中集合和影响行数含义；
- 序列、锁、事务、提交/回滚及异常后的控制流；
- DatabaseKind 分支、动态 SQL 最终模板和结果读取代码。

简单语法替换可以写出静态等价推导，但数据库配置、字段类型会影响结果时仍须降级为条件结论。静态推导不能冒充 E2/E3。

## 5. E2/E3 的执行比较方法

执行验证使用隔离测试库、只读查询或可回滚事务，不对生产数据做试验性修改。测试数据迁移和环境建设不属于用户的代码改造责任；若环境由其他角色提供，Agent记录版本、配置、数据集标识和执行人即可。

### SELECT

- 有明确 `ORDER BY`：比较行顺序、行数、列顺序、值、NULL、类型/精度和格式。
- 无 `ORDER BY`：按结果多重集合比较，不能把偶然行序差异当成错误；重复行数量仍须相同。
- 日期时间、DECIMAL 和 CHAR 尾空格只按已确认契约规范化，不能为让测试通过随意 trim、舍入或改格式。
- 覆盖无数据、单行、多行、重复值、NULL、空串、边界日期、闰日、月末、负时差和分页边界中与该 SQL 有关的用例。

### INSERT、UPDATE、DELETE、MERGE

- 两端从同一逻辑初始数据开始；记录操作前关键表快照或可复现数据脚本。
- 比较影响行数、目标行集合、各列最终值、序列/默认值、关联表副作用和错误行为。
- 在隔离事务中执行并回滚，或重建测试数据；不能只比较“命令成功”。
- DELETE/UPDATE 特别比较命中集合，防止 NULL、空格或隐式转换扩大范围。

### 过程调用、动态 SQL、锁和事务

- 比较输入/输出参数、结果集、数据副作用、提交/回滚边界及失败后的状态。
- 动态 SQL 记录最终展开文本和参数，通用执行器通过不等于每个输入模板通过。
- 锁和并发语义必须用至少两个会话验证等待、冲突、唯一性或重复取号；单会话成功不能证明并发等价。

每次 E2/E3 记录：SQL 编号、原/目标模板哈希、数据库产品与版本、DM 兼容模式和相关参数、测试数据集标识、脱敏参数、执行时间、结果摘要、自动对比结果、异常及证据文件。不要记录密码、连接串或真实敏感业务值。

## 6. 模块完成门

Agent 在模块内部持续工作，不因单条待确认而停掉整个模块。模块内所有可确定项处理完成后，必须停在模块边界，不开始下一个二级模块，并提交[模块完成报告模板](<D:/work/company/太钢二炼钢/analysis/dameng-migration/templates/模块完成报告模板.md>)。

报告明确列出：

1. 模块范围和完整 SQL 总数；
2. 可保留、已转换、待人工、待局部信息、范围外数量；
3. 修改文件和完整原 SQL 注释检查；
4. E1、E2、E3、E4 各有多少条，分别缺什么；
5. 能否称“模块审查完成”“模块源码适配完成”“DM8 可执行已验证”“结果等价已验证”；
6. 用户需要确认的问题；
7. 建议的下一个模块，但不自动开始。

用户在模块门只需要：审核业务疑问、查看技术证据是否齐全、决定是否进入下一模块。用户无需亲自判断 SQL 语法或凭感觉证明结果相同。
