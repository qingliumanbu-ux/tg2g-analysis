### 2.2 `CHARINDEX` → 官方函数清单中查无此函数

S1 的字符串函数清单含 `INSTR`/`INSTRB`/`POSITION`/`LOCATE`/`FIND_IN_SET` 等，**没有 `CHARINDEX`**。本项目扫描未发现使用，登记备查即可。

### 2.3 Oracle `(+)` 外连接 → **证据倾向"不支持，需改写"**，与项目白名单结论相反

这是本轮最重要的发现，且与 `conversion-rules.md` 现有白名单冲突，必须提请注意：

**支持"可保留"的依据（原白名单所引）** —— S4 官方 FAQ 原文：
> 「DM 数据库和 Oracle 的语法大致相同，大部分都不需要修改，可以把 Oracle 中的语法到 DM 中执行，如果有报错的部分，需要查看系统管理员手册和程序员手册来查看相应的需要修改的语法部分。」

注意：这是**针对 Oracle 语法整体**的笼统表述，**并未单独确认 `(+)`**。原白名单把它当成了 `(+)` 的支持证据，属**引用过度**。

**反对"可保留"的依据：**

1. **官方文法里没有 `(+)`**。S2 的 `<查询表达式>` 全文法中，连接类型为 `<内外连接类型>::= LEFT|RIGHT|FULL`、`<限定连接类型>::= [<内外连接类型>] INNER | … [OUTER]`，WHERE 子句为 `<搜索条件>::=<逻辑表达式>`；`<普通表>` 的语法也未包含 `(+)`。
2. **官方平台材料明确要求改写**。S6（达梦社区·Oracle 到达梦 DTS 迁移实验记录）原文：
   > 「此外，普通视图 SQL 中还存在 Oracle 特有或高风险写法，例如：( + ) 旧式外连接，**需要改写为 LEFT JOIN**」
3. 官方 S5 在讲"连接类型 DM 数据库都支持"时，列举的是内连接、左连接、右连接、全连接、自连接——**不含 `(+)` 写法**。
4. 第三方说法互相矛盾（一说"达梦兼容 `+`"，一说"Oracle 特有的 (+) 外连接在达梦中不被支持"），按项目规则"第三方博客仅作旁证"，不作依据。

**结论**：`(+)` 应当按"需改写为 ANSI LEFT JOIN"处理，而不是记作"可保留、无方言差异"。若坚持保留，必须先做 E2 实测。

## 3. 顺带查实的两个高价值结论（与 HR 类问题直接相关）

### 3.1 空串与 NULL 的官方机理（S3、S4）

S3 原文：
> 「COMPATIBLE_MODE：兼容参数，置为 2 为兼容 Oracle 参数，在 dm.ini 中可以进行配置，**如果默认 0 的情况下，达梦视 null 不等同于空字符串，用户可能会插入空串，会导致 is null 查不出全部数据**」

S4 有一条 FAQ 标题即为：「**修改兼容性参数 COMPATIBLE_MODE=2 后，SQL 走索引查询 is null 无法查询出空字符串数据**」

→ 空串/NULL 的判定**随 COMPATIBLE_MODE 取值而变**，这正是 HR-003 与 CHANGE-388（`COALESCE(LENGTH(TRIM(SM_PLAN_NO)),0)=0`）的处理依据。**验证空值语义前必须先确认目标库的 `COMPATIBLE_MODE` 取值**，否则结论不可移植。

### 3.2 关于 `''` 与 NULL 的一条官方示例（S5）

S5 在"union all 与空字符串"一节给出：
```sql
SELECT employee_name, department_id FROM dmhr.employee WHERE ROWNUM < 5 UNION ALL SELECT 'DM2021', NULL FROM DUAL;
SELECT employee_name, department_id FROM dmhr.employee WHERE ROWNUM < 5 UNION ALL SELECT 'DM2021', ''  FROM DUAL;
```
> 「上述两条 SQL 输出结果一致。」

→ 在官方示例库（默认 `COMPATIBLE_MODE=0`）下，`''` 与 `NULL` 表现一致。可作 CHANGE-388 类改写必要性的旁证，但**仍须以目标库实际参数为准**。
