# 太钢二炼钢后台 SQL 达梦适配：可行性与执行方案

日期：2026-09-06。本文是后续执行的主方案，汇总项目分析、两份项目文档、全量检索、首批人工审查及本轮独立复核。历史材料与本文范围不同之处，以用户最新明确的后台 SQL 适配范围为准。研究阶段只读复核；随后按用户要求给已有两处转换补齐原 SQL 注释，未改变可执行内容，并将流程封装为 Skill。

## 1. 结论：方案可行，可以按源码适配任务推进

**建议采用“全量检索、逐条判断、分批转换、静态复核、列明局部待确认项”的方案。** 用户负责应用代码中的 SQL，使查询、新增、修改、删除等操作采用 DM8 支持且保持原业务含义的表达式。完整构建包、全库表结构、全量样本以及双库环境，都不是开始这项工作的统一前置条件。

可行性依据有三项：业务 SQL 及大量拼接来源可从当前源码追踪；用户确认 BM2 的连接、命令、模型、参数绑定、分页、类型转换和事务已完成达梦适配；DM 官方手册能支持常用语法的保留或改写判断。部分 Oracle 风格写法在 DM 中已有对应支持，因此“全部审查”不等于“每条都改”。[DM 查询语句](https://eco.dameng.com/document/dm/zh-cn/pm/check-phrases)、[DM 函数手册](https://eco.dameng.com/document/dm/zh-cn/pm/function.html)

需要收紧原方案的两点：一是以完整 SQL 及其生成、执行路径为转换单位，不能按关键词或文件命中直接批量替换；二是源码外未取得的 SQL、依赖未知类型或平台映射的语句，必须单列，不能记作完成。其余能够确定的转换持续推进。

当前可以交付源码适配及可核查的处理记录。实际目标 DM8 执行是否通过，要有对应执行记录；本轮没有该记录，也不把源码适配扩大成数据库迁移或上线验收承诺。

后续使用项目专用 **[taigang-dm8-sql Skill](<D:/work/company/太钢二炼钢/analysis/skills/taigang-dm8-sql/SKILL.md>)** 执行上述流程。输入本批模块或服务范围，输出原 SQL 注释、必要源码转换、处理记录和人工复核项。Skill 统一步骤与格式，不把有歧义的业务判断自动替用户决定。

## 4. 转换规则：支持的保留，不等价的逐项处理

| 类别 | 处理原则 |
|---|---|
| 普通 CRUD、连接、分组、集合查询 | 核对完整结构后保留兼容语法；不为增加修改量而重写。 |
| NVL、DECODE、TO_DATE、ROWNUM、NEXTVAL 等 | DM 有相关支持，按实际参数、类型、日期格式、排序位置和会话使用方式判断；不做函数名全局替换。 |
| SYSIBM、DB2 日期表达式及其他方言 | 恢复原意，再选择 DM 对应写法；辅助表、系统目录、时间差不能共用一条替换规则。 |
| 时间计算 | 分清日历日差、经过时长、完整分钟/小时及月年估算，保持起终点、单位、取整和业务阈值。 |
| 空串、NULL、隐式转换 | 按既定目标模式和相关字段判断，尤其检查 UPDATE/DELETE 的命中条件，不能静默扩大操作集合。 |
| 元数据和字符长度 | 保持应用期望的类型分类、列别名、精度和字符/字节单位。目录名称兼容不代表返回值契约自动一致。 |
| 序列、锁、事务相关 SQL | 审查取值和锁定语句、选路及调用边界；保持既有提交/回滚和绑定方式，避免顺便重构业务流程。 |
| 动态 SQL | 同时核对产生端、拼接片段、参数、最终模板及执行端；只改执行包装函数不足以完成适配。 |
| 多库分支 | 确认 DM 实际进入哪个路径。没有平台定义时不发明枚举；保留分支结构，仅处理目标路径所需 SQL。共用路径的影响要记录。 |

特别注意：DM 的 DATEDIFF 计算单位边界；DB2 两参数 TIMESTAMPDIFF 使用不同的时长表示和部分估算规则，不能把函数名相近当作等价依据。本次还发现 DM 迁移 FAQ 的一个单位转换示例与 IBM 定义不一致，因此规则必须交叉核对源语义与目标函数手册。[DM 函数手册](https://eco.dameng.com/document/dm/zh-cn/pm/function.html)、[IBM TIMESTAMPDIFF](https://www.ibm.com/docs/en/db2-for-zos/13.0.0?topic=functions-timestampdiff)

### 原 SQL 注释与人工复核约定

**每处实际改写，先将完整原 SQL 注释保留，再写活动的 DM8 SQL。** 注释包含稳定编号、原意、改写原因、保持的业务口径和必要前提；多行 SQL 连同拼接和参数完整保留，不只截取改变的函数。重复处理同一 SQL 时保留最初原句一份，更新活动版本及说明。注释格式见 [Skill 注释规范](<D:/work/company/太钢二炼钢/analysis/skills/taigang-dm8-sql/references/comment-format.md>)。

扫描时分别统计活动 SQL 与保留原句的注释，不能把历史注释中的旧方言反复列成待转换问题。不支持注释的配置格式使用紧邻的说明文件保存原文，不破坏配置语法。所有注释和记录保护真实凭据。

用户已明确可以人工复核日期、空值等语义问题。因此，无法从当前证据确定的条目进入[待人工复核 SQL 清单](<D:/work/company/太钢二炼钢/analysis/dameng-migration/待人工复核SQL清单.md>)，写明原句、位置、建议及前提、不同选择的结果影响和一个明确问题。收到真实答复后记录结论并处理该项，其他明确 SQL 持续推进。首批为输入时间格式、小时/分钟统计口径、无计划号删除集合三项。

## 5. 后续执行顺序

### 第一步：整理可持续更新的 SQL 台账

沿用现有 CSV/JSON 和分析目录，无需另建任务平台。保留原扫描快照，为后续改动增加当前版本记录；更新清单生成逻辑时保留人工结论。现有生成器会在源文件哈希变化时停止，不能直接拿旧快照反复覆盖人工审查结果。

每条 SQL 记录：编号、模块/文件/函数/位置、来源类型、完整模板与关键变体、参数及结果含义、原 SQL 注释位置、DM 写法或保留决定、依据、局部依赖、分支影响、人工结论（如有）、静态复核状态。行号配合文件版本定位，避免改几行后证据失效。

以数据库调用点和字符串来源反向核对关键词扫描；未命中、注释、历史副本、外部配置、二进制材料都保留处置状态。归档发现独有源码时单列其身份，不盲改多个副本。

**完成标志：** 本批完整 SQL 可定位，每项知道为什么处理或暂不处理，文件数与 SQL 数分别统计。

### 第二步：以 WMSM 作为首个模块完成门

先保护 TMSM、WMSM 两处已有改动，一次只推进一个二级模块。首个建议模块为 WMSM：先定义 `Server/WMSM` 及其直接 SQL 来源的分母，接续 wmfm01_inq，再覆盖模块内全部活动 SQL。已有改动继续作为局部记录；逐条补齐残留表达式。

WMSM 内部持续处理确定项；全部在手 SQL 完成分类和确定项转换后，按[模块完成与 SQL 等价性验收规范](<D:/work/company/太钢二炼钢/analysis/dameng-migration/模块完成与SQL等价性验收规范.md>)提交报告并停止。报告分别说明源码适配、DM8 可执行和结果等价证据。用户审核后再决定是否进入 TMSM；TMSM 的时间格式或时长口径继续使用现有 HR 项，不由 Agent 代选。

**完成标志：** WMSM 每条 SQL 都有保留、已转换或待确认结论；未完成项不被算进已完成数量；模块报告已经交付，下一个模块尚未开始。

### 第三步：公共 SQL 与业务模块分批推进

用户通过模块门后，按选定的下一个二级模块继续。模块内先处理复用范围大的公共库调用、数据库选路、时间函数、序列锁、元数据访问，再推进普通及复杂 CRUD。公共库按实际调用者评估影响，不自动归为“改一处全部解决”。

每批只改有依据的差异，保持原编码、换行、参数、返回列、排序、聚合、读写条件和事务控制。完成批次后复搜旧模式、检查完整语句拼接及源码差异。剩余关键词命中可以有合理保留决定，不能以“所有 Oracle 字样清零”为目标。

**完成标志：** 本模块有可审查的代码差异、SQL 决定、残留说明和 E1—E4 证据状态，没有混入无关业务修改；模块报告交付后停止等待审核。

### 第四步：补齐动态来源与交付清单

动态 SQL 从第一批起并行登记，取得实际文本就随对应模块转换。重点包括 TMMTP 查询配置、TGCPMSI01.SQL_CONTEXT、TED54 参数，以及平台外置数据集定义。只需要相关 SQL 模板和参数定义，不需要整表数据或迁移权限。

最终交付源码修改、逐条转换台账、规则依据、覆盖报告和未取得/未确认项清单。另列库内对象、平台组件和部署身份等外部依赖，明确应用侧还需要什么契约。没有拿到的动态 SQL 不能从报告中消失，也不能记作已适配。

**完成标志：** 在手源码范围可核对，外部 SQL 缺口明确，整体完成比例的分母与未完成项公开。

## 6. 完成标准与局部输入

每条 SQL 的处理状态使用：**待审查、可保留（已复核）、已转换（已复核）、待人工复核、待局部信息、范围外/历史材料**。代码已改但语义仍待确认的，保持部分处理状态。运行结果单独记录为“未执行/目标 DM8 已验证”，不能和源码状态混用；人工确认也不代表数据库执行通过。

源码适配批次验收检查：

1. 完整 SQL 和主要拼接变体有处置决定；查询、新增、修改、删除及辅助语句均覆盖。
2. 改写有语法依据，参数顺序、结果列、空值、时间含义及操作条件保持；不能确定的差异有明确标记。
3. 数据库分支与动态 SQL 来源已追踪；无法取得的外部文本有单列记录。
4. 完整原 SQL 已按要求注释保留；差异、编码和换行检查完成，活动残留逐项解释，台账与当前代码一致。
5. 所有已取得条目关闭后才称该范围源码适配完成；待确认条目仍是未完成工作，不能用交付清单代替其转换。

后续如有适用的目标环境，可追加单条 SQL 或应用调用验证。尤其是日期边界、空值影响的删除集合、排序分页、锁行为等；这属于进一步确认运行结果，不要求当前负责人接手迁库和构建包工作。本轮未构建、未运行数据库，也未创建整套测试工程。

| 可能需要的局部信息 | 用于哪些语句 | 信息尚缺时 |
|---|---|---|
| DM8 小版本、既定兼容模式及相关日期/空串参数 | 配置影响结果的日期、空值和类型表达式 | 不自行设置模式；继续处理无此依赖的条目。 |
| BM2 的 DatabaseKind 定义和 DM 实际返回值 | 分支选路、默认分支及取号锁语句 | 只暂挂相关分支，不索要整套平台运行包。 |
| 某字段的类型/长度，某参数的日期格式 | 隐式转换、元数据长度及时间解析 | 只索取字段或参数契约，不要求全库 DDL 和样本。 |
| 配置中的生效 SQL 及参数定义 | 源码外的动态查询 | 保持“文本未取得”，取得后转换；不要求迁移配置表。 |
